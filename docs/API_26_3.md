# Minecraft 26.3 + Fabric API 0.165 — notes verified while building GambleCraft

Everything here was checked with `javap` against the 26.3 client jar or the Fabric API jars, or by running the game.
Tutorials for 1.21.x are often wrong for 26.x.

## Build
- Loom 1.19.3 needs Gradle ≥ 9.8 (wrapper 9.8.2). No mappings line: 26.x ships unobfuscated (Mojang names).
- `loom { splitEnvironmentSourceSets() }`; `fabricApi { configureTests { createSourceSet = true; enableGameTests; enableClientGameTests } }`
  gives the `gametest` source set and `runGameTest` / `runClientGameTest`.
- Client gametests: `ClientGameTestContext#clickScreenButton(key)` compares the button text with the translation of the key
  **without arguments**, so buttons whose label has `%s` arguments cannot be clicked that way.

## Renames and moved API
- `ResourceLocation` → `Identifier`; `GuiGraphics` → `GuiGraphicsExtractor`; screens draw in `extractRenderState` / `extractBackground`.
- The current screen lives on `Minecraft.gui`: `client.gui.screen()`, `client.gui.setScreen(...)`.
- `Player#sendOverlayMessage(Component)` (action bar); `Player#drop(stack, throwRandomly, Prediction)`.
- `ItemParticleOption(type, ItemStackTemplate)`; `ItemStackTemplate.fromNonEmptyStack(stack)`.
- `SimpleContainer` has no listeners: override `setChanged()` instead.
- Vanilla entity type constants are in `EntityTypes` (e.g. `EntityTypes.MARKER`); `EntityType` keeps the builder.
- Saved data: `SavedDataType(id, Supplier, Codec, DataFixTypes|null)`, `level.getDataStorage()` returns `SavedDataStorage`.
- Structure templates: `server.getStructureTemplateManager()`; `ServerLevel#structureManager()` is the *feature* manager.

## Items and models
- `new Item(new Item.Properties().setId(ResourceKey.create(Registries.ITEM, id)))`; vanilla `Items.registerItem` is private.
- Spawn eggs: `new SpawnEggItem(props.spawnEgg(type))` and an ordinary `items/*.json` + texture.
- Item model definitions: `assets/<ns>/items/<id>.json`; `select` / `range_dispatch` on `minecraft:custom_model_data`
  (strings / floats) work for per-stack models.

## Entities and rendering
- Renderers: `createRenderState` → `extractRenderState(entity, state, partial)` → `submit(state, PoseStack, SubmitNodeCollector, CameraRenderState)`.
- Custom quads: `collector.submitCustomGeometry(pose, RenderTypes.entityCutout(tex), (pose, consumer) -> ...)`;
  vertices `addVertex(pose, x, y, z).setColor().setUv().setOverlay().setLight().setNormal(pose, ...)`.
- Register with vanilla `EntityRenderers.register` (made accessible by Fabric's transitive access wideners) and
  `ModelLayerRegistry.registerModelLayer(layer, LayerDefinition supplier)`.
- Do not invent entity event ids for `Level#broadcastEntityEvent`: the client handles some ids for specific mobs by casting
  (id 63 crashed with a Sniffer cast). Send a custom payload to `PlayerLookup.tracking(entity)` instead.
- Keyframe animations: `AnimationDefinition.bake(root)` → `KeyframeAnimation.apply(AnimationState, ageInTicks)` or
  `apply(millis, scale)`; rotations are **added** to `xRot/yRot/zRot` (`ModelPart#offsetRotation`).
- Blockbench → Minecraft model space: rotate 180° about Z (renderers apply `scale(-1,-1,1)`), so positions are
  `(-x, 24 - y, z)` and rotations `(-rx, -ry, rz)`; `KeyframeAnimations.posVec` already negates Y. See `tools/bbmodel_to_java.py`.

## Worldgen
- Structure NBT (DataVersion 5023): palette entries are `{id, properties}`; entities `{pos, blockPos, nbt}`.
- Village houses connect with a jigsaw `minecraft:building_entrance` → pool `minecraft:village/<type>/streets`.
- `StructureTemplatePool.rawTemplates` (final List, may be immutable) and `templates` (ObjectArrayList) are private:
  add pieces via an `@Accessor`/`@Mutable` mixin at `ServerLifecycleEvents.SERVER_STARTING`.

## Networking and menus
- `PayloadTypeRegistry.serverboundPlay()/clientboundPlay().register(type, codec)`; `ServerPlayNetworking.registerGlobalReceiver`.
- Menus with open data: `fabric-menu-api-v1` `ExtendedMenuType(factory, StreamCodec)` + `ExtendedMenuProvider`.
- `UseBlockCallback` returning `SUCCESS` on the client still sends the use packet, so the server-side callback runs too.

## Learned in F4 (village lottery)
- **Villager trade tags and `trade_rebalance`**: appending to `data/minecraft/tags/villager_trade/<profession>/level_N.json` with `replace:false` works, but the experimental `trade_rebalance` pack (enabled in the gametest server) ships `replace:true` tags for **librarian** and **armorer** (levels 1-5), which wipes added entries. Add custom trades to other professions.
- **Blocks with `FACING` need `rotate`/`mirror` overrides** (`state.setValue(FACING, rotation.rotate(...))`, `state.rotate(mirror.getRotation(...))`). Without them a structure placed with a rotation (villages rotate every piece) keeps the unrotated facing.
- **Block model UVs**: a face of an element that sticks out of the 0..16 cube (e.g. y 12..22) gets an auto-UV outside the texture; give such faces an explicit `uv`.
- **`ServerPlayer.snapTo` does not reach the client**; in tests use `player.connection.teleport(x, y, z, yaw, pitch)`.
- **Client gametest mouse drags**: `TestInput.setCursorPos` moves only register as drags when frames run between them, so call `context.waitTick()` after each move. LWJGL is not on the gametest compile classpath (left button = `0`).

## Learned with scratch cards on blocks
- The window is **SDL3**, not GLFW: hide/show the OS cursor with `org.lwjgl.sdl.SDLMouse.SDL_HideCursor()/SDL_ShowCursor()`.
- Camera: `Minecraft.gameRenderer.mainCamera()`; `Camera.getFov()` (degrees, vertical), `forwardVector()/upVector()/leftVector()`, `position()`. Enough to cast a ray from the mouse and to project world points back to GUI coordinates.
- The player's arm with skin: bake `ModelLayers.PLAYER` / `PLAYER_SLIM`, take `getChild("right_arm")` (the sleeve is its child), zero its pivot and submit it with `collector.submitModelPart(part, pose, RenderTypes.entityTranslucent(skin), light, OverlayTexture.NO_OVERLAY, null)`. Skin: `player.getSkin().body().texturePath()`, `skin.model() == PlayerModelType.SLIM`.
- Third-person arm pose of other players: inject at TAIL of `AvatarRenderer.extractRenderState(Avatar, AvatarRenderState, float)` and set `state.rightArmPose`/`leftArmPose` (e.g. `HumanoidModel.ArmPose.BRUSH`).
- `PoseStack` has `rotateDegrees(Axis, deg)`; `mulPose` only takes a `Matrix4fc`.
- Do not build `ItemStack`s in static initialisers of client classes that load early (mixins, init): "Components not bound yet".
- The first mouse move after a screen opens is ignored by `MouseHandler`; client tests need a small nudge before a hover screenshot.
- Multiplayer paths can be tested in a client gametest with Fabric's `FakePlayer.get(level)` as the other player: packets to it are dropped, packets it causes reach the real client.
- Fabric `EntityTrackingEvents.START_TRACKING` fires after the spawn packet, a good place to send an entity's extra state.

## Learned in F5 (suit, tailor, chips, cashier)
- Armour: `new ArmorMaterial(durability, Map<ArmorType,Integer>, enchantability, Holder<SoundEvent>, toughness, knockback, TagKey<Item> repair, ResourceKey<EquipmentAsset>)`; asset key via `ResourceKey.create(EquipmentAssets.ROOT_ID, id)`; items with `new Item.Properties().humanoidArmor(material, ArmorType.X)`. Textures: `assets/<ns>/equipment/<name>.json` with `humanoid` / `humanoid_leggings` layers → `textures/entity/equipment/humanoid[_leggings]/<name>.png` (64x32, transparent pixels show the skin).
- Villager professions are records: `new VillagerProfession(name, heldJobSite, acquirableJobSite, requestedItems, secondaryPoi, workSound, Int2ObjectMap<ResourceKey<TradeSet>>)`; trades are data (`trade_set/<prof>/level_N.json` → `#ns:<prof>/level_N` tag of `villager_trade` files). POI: vanilla `PoiTypes.register(BuiltInRegistries.POINT_OF_INTEREST_TYPE, key, states, tickets, range)` is public (Fabric's `PoiHelper` is deprecated for removal). Add the POI to `minecraft:acquirable_job_site` so unemployed villagers take it. Profession texture: `textures/entity/villager/profession/<name>.png` (+ `.mcmeta` hat) and the zombie_villager copy.
- Colour families are collections now: `Items.DYE`, `Items.WOOL`… are `ColorCollection<Item>`, `Items.COPPER_BLOCK` is a `WeatheringCopperCollection<Item>`. JSON ids (`minecraft:black_dye`, `minecraft:copper_block`) are unchanged; in Java look them up by id. An `Object[][]` table hides such type changes until runtime.
- Blockbench `java_block` exports name textures after the file only (`"0": "spruce_planks"`), so map them to real ids after export (tools/gen_f5_assets.py `finish_models`).
- Item display transforms rotate about the middle of the block (8, 8, 8): keep thin models centred there. Blockbench's first-person preview did not match 26.3's first-person placement for a flat 3D chip; a `minecraft:select` on `display_context` showing the flat icon in first person is the reliable route.
- Velocity set on a player on the server only moves them once the client hears of it: send `new ClientboundSetEntityMotionPacket(player)` on `player.connection` (`ServerEntity` checks `Entity.needsSync`; `hurtMarked` is gone). `PushReaction.BLOCK` is now `IMMOVEABLE`.

## Learned in F6 (casino)
- `GameTestHelper.makeMockServerPlayerInLevel()` always answers `isCreative() == true` (setGameMode does not change it); test survival-only rules with Fabric's `FakePlayer.get(level)`.
- Abilities changed on the server (`getAbilities().flying`) reach the client only after `player.onUpdateAbilities()`.
- A client gametest can use a real generated world: `worldBuilder().setUseConsistentSettings(false).adjustSettings(s -> { s.setSeed(..); s.setWorldType(s.getNormalPresetList().getFirst()); })`, then `server.overworld().findNearestMapStructure(tag, pos, 100, false)` finds a structure like /locate.
- Structure regions: `level.structureManager().getStructureWithPieceAt(pos, holder -> holder.is(key))` — only for structures that generated naturally (a template placed by hand has no StructureStart).
- Jigsaw structure JSON (26.3): `type minecraft:jigsaw`, `start_pool`, `size`, `start_height`, `project_start_to_heightmap`, `max_distance_from_center`, `terrain_adaptation` (`beard_box` levels the ground under a building), `use_expansion_hack`; template pools are `{elements: [{element: {element_type: minecraft:single_pool_element, location, processors, projection}, weight}], fallback}`.
- Chains are `minecraft:iron_chain`; `Blocks.GREEN_WOOL` and friends are colour collections now (like items).
- NPC structure entities: villagers take `VillagerData: {type, profession, level}`; armour stands take `equipment: {chest: {id, count}, ...}`.
- `RenderTypes.entityCutout` does not cull back faces in 26.3 (the culling one is `entityCutoutCull`); there is no `entityCutoutNoCull`.

## Learned in F7 (slots, roulette)
- Block entities: `new BlockEntityType<>(factory, Set.of(block))` registered in `BuiltInRegistries.BLOCK_ENTITY_TYPE`; sync to clients with `getUpdatePacket() -> ClientboundBlockEntityDataPacket.create(this)` and `getUpdateTag(registries) -> saveCustomOnly(registries)`, pushed by `level.sendBlockUpdated(pos, state, state, 3)`.
- Block entity renderers: `BlockEntityRenderer<T, S extends BlockEntityRenderState>` with `createRenderState`, `extractRenderState(be, state, partialTick, cameraPos, crumbling)` (call `BlockEntityRenderState.extractBase`) and `submit`; `shouldRenderOffScreen()` for drawings larger than the block; register with `BlockEntityRenderers.register`.
- An `EntityBlock` gets a block entity on every state during world generation (ProtoChunk); a multi-block whose other half returns null logs "Tried to load a block entity ... but failed". Give every half one and let only the main half tick and draw.
- Block removal hooks: `affectNeighborsAfterRemoval(state, level, pos, movedByPiston)` on the block and `preRemoveSideEffects(pos, state)` on the block entity (onRemove is gone).
- `ChunkPos.pack()` (not toLong); `PoseStack.rotate(Quaternionf)` for the camera orientation.
- Blockbench's `risky_eval` refuses code containing `//` comments or `console.`; tools/bb_build.py strips comment lines from blockbench/build_block.js.

## Learned in F8 (plinko, wheel, crash, dice, kiosk)
- `BlockEntityRenderer` has no render-box override in 26.3 (only `shouldRenderOffScreen`, `getViewDistance`, `shouldRender(be, cameraPos)`); a drawing far above the block (the crash rocket) just needs `shouldRenderOffScreen() == true`.
- `GameTestHelper.onEachTick(Runnable)` runs every tick next to `succeedWhen`; the level (and its block entity tickers) ticks before the test listeners in the same server tick.
- `Container` (and so `Inventory`) is `Iterable<ItemStack>`.
- A value the server must keep from clients (the crash point) can be dropped from `getUpdateTag` while it is secret; the client's `loadAdditional` then falls back to its default.

## Learned in F9 (casino security)
- Loot table entries take their functions under `"modifier": [{"type": "minecraft:set_count", ...}]` (not `"functions"`/`"function"`); an unknown key is silently ignored, so a table with `"functions"` loads but drops plain items. Number ranges need `{"type": "minecraft:uniform", "min", "max"}`.
- `EnchantmentHelper.updateEnchantments(stack, mutable -> ...)` does nothing to a stack without an `enchantments` component; armour and tools have one by default.
- Villagers walk to a job site only in the IDLE, WORK or PLAY activity (`GoToPotentialJobSite`), never while resting at night: set the time (`GameTestHelper.setTime`) in tests that wait for a profession.
- Blocks: `Block.UPDATE_SKIP_BLOCK_ENTITY_SIDEEFFECTS` sets a block without its block entity's removal side effects (no container drops); `BlockEntity.loadStatic(pos, state, tag, registries)` + `level.setBlockEntity(...)` restores a saved one. `level.levelEvent(2001, pos, Block.getId(state))` plays the break particles and sound.
- Fabric has no block-placed event: a mixin on `BlockItem.place(BlockPlaceContext)` (HEAD/RETURN) sees every placed block with the player; `BlockPlaceContext.getClickedPos()` is already the placement position.
- `ServerLevel.getEntity(UUID)` finds loaded entities; Fabric `FakePlayer`s are neither on the player list nor in the level, so game tests aim mobs at them with `setTarget`.
- `LivingEntity.swing(hand, SwingAnimation.DEFAULT, true)`; `Item.Properties.useCooldown` exists, but a plain `player.getCooldowns().addCooldown(stack, ticks)` is enough.
- `StructureStart.getPieces().getFirst()` of a jigsaw casino is a `PoolElementStructurePiece`: `StructureTemplate.calculateRelativePosition(new StructurePlaceSettings().setRotation(piece.getRotation()), localPos).offset(piece.getPosition())` turns a template position into the world one.

## Learned in F10 (the casino's people)
- `Inventory.contains(ItemStack)` compares components too (a renamed card is "not contained"): count with `inventory.countItem(item)`. `Player.drop(stack, bool)` is gone: `inventory.placeItemBackInInventory(stack, Prediction.SERVER_ONLY)` gives or drops. `Inventory.clearOrCountMatchingItems(predicate, boolean, max, craftSlots)` gained a boolean.
- Colour block collections again (`Blocks.RED_CARPET` does not exist); `PushReaction.DESTROY` is now `POPPED`.
- Drinks: `Item.Properties().component(DataComponents.CONSUMABLE, Consumable.builder().consumeSeconds(1.6F).animation(ItemUseAnimation.DRINK).sound(SoundEvents.GENERIC_DRINK).onConsume(new ApplyStatusEffectsConsumeEffect(effects)).build()).usingConvertsTo(Items.GLASS_BOTTLE)`.
- A humanoid mob in armour: `HumanoidMobRenderer` with `new HumanoidModel<>(ctx.bakeLayer(ModelLayers.PLAYER))` (64x64 player skins) plus `new HumanoidArmorLayer<>(this, ArmorModelSet.bake(ModelLayers.PLAYER_ARMOR, ctx.getModelSet(), HumanoidModel::new), ctx.getEquipmentRenderer())`; it holds items out of the box. `Item.Properties.sword(ToolMaterial, damage, speed)` makes a weapon (`DataComponents.WEAPON`).
- Server-to-client components: `ComponentSerialization.TRUSTED_STREAM_CODEC`; item stacks `ItemStack.OPTIONAL_STREAM_CODEC`.
- Filled maps to a spot: `MapItem.create(level, x, z, scale, true, true)`, `MapItem.renderBiomePreviewMap`, `MapItemSavedData.addTargetDecoration(stack, pos, "+", MapDecorationTypes.RED_X)`; buried loot: `chest.setLootTable(BuiltInLootTables.BURIED_TREASURE)` + `setLootTableSeed`.

## Learned in F11 (polish)
- Own particles without writing a particle class: register the type with Fabric (`FabricParticleTypes.complex(ColorParticleOption::codec, ColorParticleOption::streamCodec)` or `simple()`), then on the client `ParticleProviderRegistry.getInstance().register(type, FallingLeavesParticle.TintedLeavesProvider::new)` (tinted fluttering flakes) or `GlowParticle.WaxOnProvider::new` (sparkles); the sprites come from `assets/<ns>/particles/<name>.json` listing textures under `textures/particle/` (the particles atlas picks up every namespace).
- Sounds: `Registry.register(BuiltInRegistries.SOUND_EVENT, id, SoundEvent.createVariableRangeEvent(id))` plus `assets/<ns>/sounds.json`; tools/gen_sounds.py synthesises them with numpy and encodes Ogg Vorbis with ffmpeg (`-c:a libvorbis`).
- HUD drawing with a transform: `graphics.pose()` is a JOML `Matrix3x2fStack` (`pushMatrix`, `translate(x, y)`, `scale(sx, sy)`, `popMatrix`).
- Villager trades for an explorer map to a modded structure: a `villager_trade` with `given_item_modifier: [{type: minecraft:exploration_map, destination: "#ns:tag", decoration: ...}, {type: minecraft:filtered, ...}]`, listed in `minecraft:tags/villager_trade/<profession>/level_N`.

## Learned with the sportsbook add-on (a second Loom project)
- The non-remapping `net.fabricmc.fabric-loom` has no `namedElements` configuration. A subproject that builds on the
  root mod depends on `rootProject.sourceSets.main.output` (and `clientImplementation rootProject.sourceSets.client.output`)
  and lists the root's source sets in its own `loom { mods { "gamblecraft" { sourceSet("main", ":"); sourceSet("client", ":") } } }`
  so the dev runs load both mods. Its jar holds only its own classes.
- `loom { runs.configureEach { vmArg "-D..." } }` reaches the `runGameTest` / `runClientGameTest` runs too.
- Coloured icons in item descriptions: a bitmap font `assets/<ns>/font/<name>.json` (`file` is relative to `textures/`,
  private-use characters like ``) and `Style.EMPTY.withFont(new FontDescription.Resource(id)).withColor(0xFFFFFF)`.
- `Checkbox.builder(Component, Font).pos(x, y).selected(b).onValueChange((box, value) -> ...).tooltip(Tooltip.create(...)).maxWidth(w).build()`;
  `EditBox` has `setResponder`/`setMaxLength`/`setHint` but no filter: parse the text where it is used.
- `StreamCodec.composite` takes up to 14 fields.
- Permissions: `player.permissions().hasPermission(Permissions.COMMANDS_GAMEMASTER)`, `server.isSingleplayerOwner(player.nameAndId())`;
  command nodes `.requires(Commands.hasPermission(Commands.LEVEL_GAMEMASTERS))`.
- Another mod's creative tab: `CreativeModeTabEvents.modifyOutputEvent(ResourceKey<CreativeModeTab>)`.
- `Item.inventoryTick(ItemStack, ServerLevel, Entity, EquipmentSlot)` is server-only now: a good place to bring an item's
  components up to date (they reach the client by themselves).
- `GameTestHelper.makeMockServerPlayerInLevel()` puts the player at the world's 0,0,0, not in the test area: move it
  (`setPos`) before anything that checks reach.
- Sports feeds as of November 2026: ESPN's scoreboard refuses date ranges (`dates=A-B` → 400) and no longer carries
  `soccer/pol.1`; TheSportsDB's free key `123` answers 429 (`Retry-After: 30`) to bursts and also caps requests per
  hour, so read football there by matchday (`eventsround.php`) rather than day by day.
